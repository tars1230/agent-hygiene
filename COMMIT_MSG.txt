Add handle type breakdown: turn "many handles" into an actionable root cause

Competitors can only report "this process has many handles". This adds the
layer they all lack: which kind of handles, which dead pids they point to,
and how many processes are sharing the leak.

Measured on Weixin main process (pid 28208), 178033 handles:
  Event 80849 (45.4%) + Token 61193 (34.4%) + Process 30632 (17.2%)
  - 29641 of the Process handles (96.8%) point at already-exited processes,
    and only 3 source pids are responsible: 13092 / 20764 / 425444
  - all 61193 Token handles are duplicate copies of the same user token
    (TARS\Administrator, identical LUID 6fa1c)
  - a system-wide scan (465055 handles) shows those same 3 pids are held by
    15+ unrelated processes, 43076 handles in total
  - pid 13092 is the known explorer.exe thread-leak sample, so the leak is a
    knock-on effect of that crash, not a Weixin bug
  - ratio check: ~6 leaked handles per dead process (1 Process + 2 Token +
    3 Event) = 172674 / 178033 = 97%

Tools:
  tools/handle_type_breakdown.py  type breakdown + dead-process clustering,
                                  cross-checked against Get-Process
  agent_hygiene_audit.py          new section 4c, runs only for handle anomalies

Two traps worth documenting:
  - Sysinternals Handle without -a lists only NAMED handles: 487 lines for
    178033 real handles, stopping at slot 4020. That inverts the conclusion.
  - Handle.exe is Microsoft proprietary, so _vendor/ is gitignored and the
    audit report shows [skip] with download instructions when it is absent.

Handles are a steady high-water mark, not a growing leak: minute sampling
shows 178028 -> 178037 -> stable at 178033.
