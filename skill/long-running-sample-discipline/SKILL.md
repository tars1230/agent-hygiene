# 长跑采样纪律

> 定位：**跨项目的通用方法论 Skill**。不绑定任何具体指标。
> 与 `diagnostic-tool-trust` 的关系：那个管「工具可不可信」，这个管「**样本够不够、结论绑不绑窗口**」。

## 何时用

- 要连续采样同一指标并下趋势结论
- 要判断「在持续增长」还是「已经稳态」——**这两者的处置完全不同**
- 需要产出一份可复核的时间序列
- 采集中途可能会被环境打断（会话结束、后台回收、机器休眠）

## 痛点

采样失败的三种典型死法，都很安静：

| 死法 | 现象 | 后果 |
|---|---|---|
| **攒在内存里** | 进程被杀 → 样本全丢 | 白跑，且不知道丢在哪一轮 |
| **固定阈值判突跳** | `Δ>500` 就算突跳 | 匀速增长时**每段都被标成突跳**，等于没判 |
| **结论不绑窗口** | 「它每分钟涨 675」 | 三次采样实测 +1022 / +20 / **−3.2**，差两个数量级还变号 |

## 四条纪律

### 1. 增量落盘，不攒在内存

- **每轮**采完立刻 append 到 JSONL（一行一轮），不要攒到结束再写
- 好处：被杀了也保留已采到的部分，还能从文件反推**死在哪一轮**
- 配套：**记录每轮时间戳**，否则事后无法对齐窗口

```python
# 每轮结束立刻 append + flush
with open(out, 'a', encoding='utf-8') as f:
    f.write(json.dumps(row, ensure_ascii=False) + '\n')
    f.flush()
```

### 2. 结论必须绑定采样窗口

写「在 **2026-10-29 15:31–15:46（14.9 分钟）** 的采样里，句柄总数 **−3.2/分钟**（各段速率中位数 **+0.0**）」。

**不要**写「它每分钟涨 X」或「它在增长」。理由不是措辞讲究，而是实测过：**速率是当次测量的性质，不是常数**。

必须一并报的三样：
- **时间跨度**（起止时刻 + 总时长）
- **平均速率**
- **各段速率的中位数**（比平均值更抗单点尖峰）

### 3. 突跳判定用本轮速率中位数，不用固定阈值

- 固定阈值（`Δ>500`）在匀速增长下会把**每一段**都标成突跳 → 失去区分力
- 正确做法：与**本轮各段速率的中位数**比较
- 中位数为负时（整体在降）另走分支，别硬套

### 4. 稳态 / 持续增长 / 突跳，三态分开报

| 态 | 判据 | 处置 |
|---|---|---|
| **稳态** | 总量无趋势，各段速率中位数 ≈ 0 | 别动它 |
| **持续增长** | 总量单调趋势，各段速率中位数显著 > 0 | 找**逐目标 Δ** 定位源 |
| **突跳** | 单段速率远超本轮中位数 | 查那段时间发生了什么 |

**「没找到增长源」不等于「增长来自某个容器」**。实测：新增的 Process 句柄**全部指向存活的 explorer**，
不是某个子进程容器。→ **必须看逐个目标 pid 的 Δ**，不能从「某类对象数量没变」倒推。

## 环境坑（本机实测）

### 长跑进程会被后台管理器静默回收

- `run_in_background` 起的 python 采样，**第 4~6 轮被静默杀掉**
- 特征：**无 stderr、退出码 0** —— 看起来正常结束了
- 对策：
  - 每轮增量落盘（掉了也知道掉到哪轮）
  - 用 `nohup ... &` 起，别依赖后台任务管理器
  - 跑完**核对行数**：`实际轮数 == 计划轮数`？不等就是被杀了

### PowerShell `Start-Process` 在本机不可用

- 环境变量同时存在 `Path` 和 `PATH` → 报「已添加了具有相同键的项」
- `Get-ChildItem Env:` 同样报错 → 改用 bash `nohup`

### 交叉校验不能要求完全相等

- 枚举要花几秒，期间进程会自己开/关句柄
- 正确判据：结果落在**操作前 / 操作后**两个读数**之间**即算一致

## 工作流

1. **定窗口**：这次要采多久、每轮间隔多少、总共几轮 —— 先写下来
2. **定判据**：什么算稳态、什么算增长、什么算突跳 —— 先定义，别事后挑
3. **增量落盘**：每轮 append + flush，带时间戳
4. **跑**：中途可能被杀，靠文件反推进度
5. **核**：行数 == 计划轮数？不够就补跑或如实说明只采到几轮
6. **报**：时间跨度 + 平均速率 + 速率中位数 + 三态判定 + 绑定窗口的结论

## 报告模板

```
采样窗口：<起-止>（<时长>，<N> 轮 × <间隔>）
总量：<首> -> <尾>（<Δ>）
平均速率：<X>/分钟     各段速率中位数：<Y>/分钟
最小/最大段速率：<a> / <b>
判定：<稳态 | 持续增长 | 突跳>
逐目标 Δ：<哪一类目标在涨，涨了多少>
结论：在 <时段> 的采样里是 <什么>。不代表其他时段。
```

最后那句**必须有**。这是本 Skill 的核心——它防止一个时段的观测被当成永久属性。
