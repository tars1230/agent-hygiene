# 诊断工具可信度纪律

> 定位：**跨项目的通用方法论 Skill**。不绑定任何具体工具。
> 与 `agent-hygiene` 的关系：agent-hygiene 是「内存诊断的专用工具集」，
> 本 Skill 是「不管用什么工具，都得先过这七道检查」的通用纪律。agent-hygiene 的铁律是它的实战落地。

## 何时用

- 要把某个工具的输出当**结论**用（而不只是看一眼）
- 输出的结果会导向**不可逆操作**（杀进程、删文件、改配置、发消息）
- 刚被**第三方复核**挑出问题，想知道自己哪里能改
- 要写进文档 / 报告的**数字**
- 刚给某个工具加完修复，不确定自己是不是真的修好了

## 为什么需要它

最贵的错误不是「工具报错」，而是**工具安静地给出一个自洽但错误的结果**。
本机实测过的四类真实事故，每一类都通过了「看起来正常」的表象：

| 事故 | 表面现象 | 实际真相 |
|---|---|---|
| 静默降级 | 静态分析报「native 100% 可达」 | 静态工具量的是「**声明**」环节，真跑时绑定失败只打 stderr 并返回默认值 |
| 排序类型语义 | `grep \| sort` 排十六进制 | 字符串序不是数值序（`0xBBBF0` < `0xFB4`）→ 结论完全相反 |
| 空报告全绿 | 门禁跑完报「PASS」 | 缺关键键被 `r.get(...) or 0` 兜成 0，**缺证据 ≠ 通过** |
| 副本分叉 | 仓库版改好了，线上还是旧的 | 手工 `cp` 不自动同步，**且没有任何东西报错** |

**共同点：没有一个会自己喊疼。**

## 七道信任检查

每一条都要能**给出证据**，不能只说「我检查过了」。

### 1. 工具真的跑了吗

- 看**退出码**，不看 stdout 有没有内容
- 看**产物**落没落盘（文件时间戳 / 退出码），不看「应该生成了」
- 陷阱：后台 agent 会虚报成功 → **必须验实际产物**（`git diff --stat`、文件 mtime）
- 陷阱：异常被包装成默认值 → 打印完整 cause 链 + 栈帧，不能只看最外层

### 2. 读的是对的源吗

- 是不是读到了**缓存/备份/废弃副本**而不是真源？
- 清单/索引/元数据有没有**假条目**？（实测：本图 listfile 里有个 `Scripts\war3map.j` 是假的，
  用错名字会解出垃圾**且不报错**）
- 有几个副本？**改了哪几个？**（实测：skill 三份副本，改一份不同步另外两份）

### 3. 口径对吗

- 同一个词在不同工具里含义不同：WS vs Private vs Commit —— **WS 会被 trim，不作数**
- 百分比**必须写清分母**：僵尸 29641 = 占 Process 类 89.79%（分母 33012）/
  占全部 15.48%（分母 191435）。两个数都正确，分母不同，引用时必须说清是哪个
- 计数单位要统一：**字符数 ≠ 字节数**（中文 UTF-8 一个字 3 字节）

### 4. 有没有静默降级

最隐蔽的一类。信号：

- 「静态 100% 可达」这类**绝对化的漂亮数字**
- 工具对缺失项**返回默认值而不是报错**
- 工具输出里混着 `[skip]`

做法：**真跑一遍并抓 stderr**。静态工具量的往往是「声明」环节，不是「执行」环节。

> 判据：**数字太干净 = 可疑信号**。

### 5. 参照系选对了吗

用来做对比时，绝对值和相对值都可能骗人：

- **组内中位数会被离群值「自己」抬高** → 用 **leave-one-out 同伴中位数**（把自己剔除后再算）
  实测：190000 + 243，普通中位数 95121.5，倍数只有 2.0（异常被完全藏住）；剔除自己后报出 **781.9x**
- **单实例时组内中位数 == 自己**，倍数恒为 1.0 → 单实例要用**全局中位数 P50** + 独立下限
  （实测 `SOLO_HANDLES_ABS=20000` 才能兜住 `wetype_renderer` 的 22012 句柄；用 50000 会漏）
- **高分位不能做兜底参照系**：实测 P99.9 在 539 个进程上等于**最大值本身**（被最大值污染）
- **绝对阈值与倍数是「与」关系**，各挡各的 —— 只看倍数会误报，只看绝对值会漏报

### 6. 结论绑定采样窗口了吗

- **速率是当次测量的性质，不是常数**
  实测：同一进程三次采样 ≈ +1022/分钟、+20/分钟、**−3.2/分钟**（中位数 +0.0）
- 所以要写「在 <时段> 的采样里是 <什么>」，不能写「它 <是/不是> 在增长」
- 「某类对象数量没变」≠「增长来自别处」→ 要看**逐个目标的 Δ**

### 7. 文档里的数字能机器复核吗

- 同一数字出现在**两份文档**时，改一处必须同步另一处
- 且要有**机器校验**，不能靠人工同步（人工同步必然漏）
- 门禁要**对原始测量值重算**，不能采信实现者自报的 `pass`
- **缺关键键 = FAIL**，不能 `or 0` 兜底

## 工作流

1. **跑**：真实执行，保留退出码和原始输出
2. **查**：按七道检查逐条过，每条写下**证据**
3. **交叉**：至少换一个独立数据源验同一结论（不同工具 / 不同时间 / 不同口径）
4. **绑**：把结论绑定到具体采样窗口和具体数字
5. **判**：不可逆操作前，把「结论 + 依据 + 将执行的确切命令」一起给用户确认

## 复述模板（给用户看结论时）

```
判定：<一句话>
依据：<原始数字，带分母> · <原始数字> · <原始输出片段>
口径：<Private/commit/句柄数/…>，采样窗口 <起-止>
对照：<交叉验证的第二个来源>
建议命令：<确切可复制的命令，含前置守卫>
不确定：<明确列出「待验证」的项，不装确定>
```

## 禁则

- ❌ 拿估算冒充实测
- ❌ 把「能跑出自洽结果」当成「对」
- ❌ 把「结论对」当成「推理链对」——**包括你自己的**
- ❌ 只报领先项，藏短板
- ❌ 在没跑通的情况下汇报「已完成」
